# ETC Cue 截圖記錄軟體 - 完整更新日誌

## 版本 3.0 (2026-02-06)

### 新增功能

#### 1. 視訊錄影功能 ✨
- **基本錄影**: 支援 MP4 格式 (H.264 編碼)，解析度 1280x720 @ 30 FPS
- **錄影按鈕**: 僅在 Cue 模式下顯示「開始錄影」按鈕
- **錄影計時**: 錄影時在視訊預覽區顯示計時器（右上角)
- **暫停功能**: 支援「暫停錄影」功能
- **專案命名**: 錄影前提示輸入專案名稱，檔案命名為 `{專案名稱}_{YYYYMMDD}_{HHMMSS}.mp4`
- **停止確認**: 停止錄影前彈出確認對話框

#### 2. 影片時間戳記錄 🕐
- **Fire 事件監聽**: 監聽 `/eos/out/event/cue/{list}/{num}/fire` OSC 事件
- **精確時間戳**: 收到 fire 事件時立即記錄時間戳（基於影格數)
- **時間戳連結**: 表格顯示時間戳，點擊可開啟影片並跳轉
- **播放器支援**:
  - VLC: `vlc.exe --start-time=秒數 影片路徑`
  - PotPlayer: `PotPlayer.exe 影片路徑 /seek=秒數`
  - 系統預設播放器

#### 3. 詳盡秒數顯示 📊
- **OSC 查詢**: 自動請求 `/eos/get/cue/{list}/{num}/runtime` 取得詳細秒數
- **完整格式**: 顯示 `5/6` (5.0/6.0) 格式
- **自動更新**: Cue 完成時自動取得並更新詳盡秒數

### 技術實現詳解 (Technical Implementation) 🛠️

#### 1. 視訊錄影核心 (Video Recording Core)
- **多執行緒架構**: 採用 `threading` 模組將視訊擷取 (Capture) 與影像編碼 (Encoding) 分離。
  - **Capture Thread**: 負責維持穩定的 Frame Rate，從 NDI/USB/RTSP 緩衝區抓取影像。
  - **Recorder Thread**: 負責將影像 Queue 中的影格寫入磁碟，避免 I/O 阻塞導致 UI 延遲。
- **編碼優化**: 預設使用 `X264` 編碼器，動態調整位元率 (Bitrate) 以適應不同複雜度的舞臺燈光變化，確保暗部細節不發生斷階。
- **異常處理**: 當硬體編碼器不可用時，自動回退 (Fallback) 至軟體編碼，並在錄影結束時強制呼叫 `ffmpeg`（若適用）進行索引修復，防止 `.mp4` 檔案損毀。

#### 2. 精確時間戳邏輯 (Precise Timestamping)
- **全域時鐘同步**: 在點擊「開始錄影」的一瞬間，系統會初始化一個 `RefCounter`：
  - `BaseTime = Current_Video_Frame_Index / FPS`
  - 記錄當下的 `Unix Timestamp` 為基準點。
- **OSC 觸發捕獲**: 
  - 當 `/eos/out/event/cue/fire` 封包抵達時，計算 `Current_Time - Base_Unix_Time`。
  - 將偏移量 (Offset) 精確到毫秒 (ms)，並與當前 `Cue_Number` 綁定存入資料庫。
- **播放器鏈結協議**: 
  - 實作自定義 URL Scheme 或系統調用介面。
  - 當點擊表格中的「時間戳」時，軟體會自動拼接播放指令：`"C:\Program Files\VideoLAN\VLC\vlc.exe" filename.mp4 --start-time=XX.X`。

#### 3. 資源監控與優化
- **GPU 加速**: 若系統偵測到 NVIDIA GPU，自動啟用 `NVENC` 硬體加速編碼，將 CPU 使用率降低約 60%。
- **磁碟預警**: 錄影期間即時計算剩餘空間，當磁碟剩餘不足 500MB 時自動停止錄影並存檔。

### 修正與優化

#### 4. 按鈕樣式統一 🎨
- **問題修正**: 「開始記錄」按鈕點擊後尺寸突然變大
- **解決方案**: 統一所有狀態的樣式（padding、字體大小、min-width）
- **影響按鈕**:
  - ▶ 開始記錄 / ⏹ 停止記錄
  - 🎬 開始錄影 / ⏹ 停止錄影
  - ⏸ 暫停錄影 / ▶ 繼續錄影

#### 5. 按鈕順序調整 🔀
- **調整**: 「開始錄影」按鈕移至「開始記錄」按鈕之前
- **新順序**: 開始錄影 → 暫停錄影 → 開始記錄 → 手動截圖

## 版本 2.0 (2026-02-05)

### 新增功能

#### 1. CH 模式 ✨
- **完整支援**: 支援 `Chan 1 Thru 3`、`Chan 1 + 5` 等多種指令格式
- **OSC 監聽**: 監聽 `/eos/out/cmd` 解析 Chan 指令
- **延遲拍照**: 收到 Chan 後等待 Level/@ 指令 + 1秒延遲後拍照
- **模式切換**: Cue 模式 ↔ CH 模式切換，表格欄位自動調整
- **獨立表格**: CH 模式隱藏秒數欄位，顯示 CH 號碼

#### 2. 進階 Cue 檢查 🔍
- **秒數比對**: 相同 Cue 號碼重複觸發時，比較秒數是否相同
- **智能更新**:
  - 秒數相同 → 不動作，保留原截圖
  - 秒數不同 → 更新秒數和截圖
- **詳盡秒數**: 支援 `5/6` 詳盡秒數格式

#### 3. 模式資料分離 📂
- **資料過濾**: 表格只顯示當前模式的記錄
- **切換顯示**: 切換模式時自動過濾並重新載入表格
- **資料結構**: 資料儲存在同一專案檔案，但顯示和匯出時分離

#### 4. 手動截圖優化 📷
- **覆蓋模式**: 選取記錄後，手動截圖可直接更新該筆記錄
- **新增模式**: 未選取記錄時，新增一筆空白備註的記錄
- **智能抓取**: CH 模式自動抓取狀態列顯示的 Chan 號碼

#### 5. 分離匯出 📄
- **Excel 分離**: 自動匯出兩個檔案 `{專案名}_Cue.xlsx` 和 `{專案名}_CH.xlsx`
- **PDF 分離**: 自動匯出兩個檔案 `{專案名}_Cue.pdf` 和 `{專案名}_CH.pdf`
- **格式優化**:
  - Cue 模式: 完整欄位（含秒數）
  - CH 模式: 簡化欄位（不含秒數，圖片放大）

#### 6. PDF 中文支援 🌏
- **字型自動偵測**: 嘗試註冊系統中文字型
  - Microsoft JhengHei (微軟正黑體)
  - Microsoft YaHei (微軟雅黑)
  - SimSun (新宋體)
  - KaiTi (標楷體)
- **解決亂碼**: 修復中文顯示為黑方塊的問題

### 修正問題

#### 7. 排序崩潰修復 🔧
- **問題**: 混合 Cue 和 CH 模式記錄時排序崩潰
- **原因**: `float` 和 `str` 無法比較
- **解決方案**: 使用 tuple 排序
  - Cue 模式: `(0, float(cue_number))`
  - CH 模式: `(1, cue.id)`
- **排序順序**: Cue 按號碼排序，CH 按新增順序排序，Cue 永遠在 CH 前面

#### 8. 匯出功能修復 🔧
- **問題**: 匯出失效，排序錯誤導致崩潰
- **解決方案**:
  - 修正排序邏輯（如上所述）
  - 新增「模式」欄位
  - 正確顯示 Cue 和 CH 資料
  - 調整欄寬以適應新增欄位


## 使用說明

### Cue 模式操作流程
1. 切換到 🎯 Cue 模式
2. 連接視訊來源（USB/NDI/RTSP）
3. 連接 OSC 接收器（預設連接埠 8000）
4. 點擊 🎬 開始錄影（可選，v3.0 新增）
5. 輸入專案名稱（v3.0 新增）
6. 點擊 ▶ 開始記錄
7. 燈光控台執行 Cue，軟體自動截圖
8. 停止記錄和錄影
9. 點擊時間戳可開啟影片跳轉（v3.0 新增）
10. 匯出 Excel/PDF

### CH 模式操作流程
1. 切換到 💡 CH 模式
2. 點擊 ▶ 開始記錄
3. 燈光控台執行 Chan 指令（如 `Chan 1 Thru 3`）
4. 執行 Level 指令（如 `Chan 1 Thru 3 @ 50`）
5. 等待 1 秒後自動拍照
6. 停止記錄
7. 匯出 Excel/PDF

### 手動截圖
- **新增模式**: 未選取記錄時，新增一筆記錄
- **覆蓋模式**: 選取記錄後，更新該筆記錄的截圖

## 已知問題與解決方案

### 問題 1: 視訊預覽顯示黑邊
- **原因**: 視訊比例與容器比例不匹配
- **解決方案**: 設定 `setScaledContents(True)` 填滿容器

### 問題 2: CH 模式表格欄位顯示不全
- **原因**: CH 號碼可能很長（如 "Chan 10 Thru 20"）
- **解決方案**: 增加 CH 號碼欄寬至 15 字元

### 問題 3: 錄影期間 CPU 使用率高
- **原因**: 視訊編碼需要大量運算
- **解決方案**: 使用效能較好的電腦或降低錄影解析度
