1. 軟體介紹

OSC to MA2 Telnet 橋接工具 是一套 Windows 桌面應用程式，可接收 OSC（Open Sound Control）訊息，並即時轉發為 grandMA2 lighting console 的 Telnet 指令，實現外部裝置（如觸控面板、手機 App、互動裝置）遠端控制 MA2 燈光系統。

工具內建 OSC 伺服器與 MA2 Telnet 客戶端，透過圖形化介面即時顯示所有收發訊號，適合燈光秀、舞台演出、互動裝置、展覽展演等場景使用。

OSC 即時橋接

接收 OSC 訊息後自動轉發為 MA2 Telnet 指令。

智慧過濾

僅處理以 /ma2 開頭的 OSC 位址，避免誤觸。

即時監控介面

終端機面板即時顯示收發的 OSC 與 Telnet 訊息。

深色/淺色主題

一鍵切換黑底或白底，適應不同作業環境。

3. 安裝與啟動

3.1 啟動前注意事項

  • 請先確認 grandMA2 主機的 Telnet Server 已開啟。
  • 確認 MA2 登入帳號與密碼正確（預設: administrator / admin）。
  • 若防毒軟體跳出提示，請允許程式執行。
  • 確認 OSC 發送端的目標 IP 與 Port 與本工具設定一致。

4.1 訊息格式辨識

終端機面板中的訊息前綴代表不同意義：

  • <-- [收到 OSC] ：表示從 OSC 發送端收到的訊息
  • --> [發送到 MA2] ：表示已轉發至 grandMA2 的 Telnet 指令
  • [MA2] ：表示與 MA2 連線相關的狀態訊息
  • [OSC] ：表示 OSC 伺服器相關的狀態訊息
  • [系統] ：表示程式內部系統訊息

5. 快速開始

5.1 基本連線設定

  1. 確認 grandMA2 主機 IP 位址（例如 192.168.1.100）。
  2. 在 grandMA2 上開啟 Telnet Server（預設 Port 30000）。
  3. 以預設參數啟動本程式，或透過命令列指定參數。
  4. 觀察終端機面板顯示 [MA2] 成功連接到 MA2 Telnet 即代表連線成功。

5.2 發送 OSC 指令測試

  1. 使用 OSC 發送工具（如 TouchOSC、OSCculator、自訂 App）。
  2. 發送 OSC 訊息到位址 /ma2，參數為完整 MA2 指令（如 Go Executor 1.1）。
  3. 或發送到位址 /ma2/Go Executor 1.1。
  4. 觀察終端機面板是否顯示收訊與轉發訊息。

6. OSC 訊息格式說明

6.1 支援的 OSC 格式

本工具僅處理以 /ma2 開頭的 OSC 位址，其餘訊息將被過濾忽略。

格式 OSC 位址 OSC 參數 轉換結果
格式 A（推薦） /ma2 完整指令字串（如 Go Executor 1.1） Go Executor 1.1
格式 B /ma2/Go Executor 1.1 可選附加參數 Go Executor 1.1 [附加參數]

6.2 範例：觸發 Executor

# 格式 A：位址為 /ma2，第一個參數是指令 OSC 位址: /ma2 OSC 參數: "Go Executor 1.1" → 轉發至 MA2: Go Executor 1.1 # 格式 B：指令寫在位址路徑中 OSC 位址: /ma2/Go Executor 1.1 OSC 參數: (無) → 轉發至 MA2: Go Executor 1.1 # 格式 B + 附加參數 OSC 位址: /ma2/SetChannel OSC 參數: 1, 255 → 轉發至 MA2: SetChannel 1 255

6.3 安全過濾機制

  • 所有不以 /ma2 開頭的 OSC 訊息會被自動忽略。
  • 終端機面板會顯示 [系統] 收到非 MA2 指令，已略過不轉發。。
  • 此機制可防止其他 OSC 訊號誤觸 MA2 系統。

7. 常見問題

Q1：終端機顯示「連接 MA2 失敗」

  • 確認 grandMA2 主機的 IP 位址是否正確。
  • 確認 grandMA2 的 Telnet Server 已開啟。
  • 確認 Port 30000 未被防火牆阻擋。
  • 嘗試在 MA2 上使用 ping 指令確認網路連通。

Q2：收到 OSC 訊息但 MA2 沒反應

  • 確認 OSC 位址是否以 /ma2 開頭。
  • 檢查 MA2 Telnet 是否已成功登入（查看終端機登入回覆）。
  • 確認發送的 MA2 指令格式是否正確。
  • 在 grandMA2 本地端手動測試該指令是否有效。

Q3：OSC 發送端無法連接到本工具

  • 確認 OSC 發送端的目標 IP 是本機區域網路 IP（非 127.0.0.1）。
  • 確認 OSC Port 與本工具設定一致（預設 8000）。
  • 確認本機防火牆允許該 UDP Port 的連入。

Q4：程式執行後終端機面板無訊息

  • 確認 OSC 發送端是否確實有發送訊息。
  • 確認 OSC 位址格式是否正確（需以 /ma2 開頭）。
  • 嘗試使用 OSC 工具發送測試訊息。

1. Overview

OSC to MA2 Telnet Bridge is a Windows desktop application that receives OSC (Open Sound Control) messages and instantly forwards them as grandMA2 lighting console Telnet commands, enabling remote control of MA2 lighting systems from external devices such as touch panels, mobile apps, and interactive installations.

The tool includes a built-in OSC server and MA2 Telnet client, with a graphical interface that displays all sent and received signals in real time. It is ideal for light shows, stage performances, interactive installations, and exhibitions.

OSC Real-time Bridge

Receives OSC messages and forwards them as MA2 Telnet commands.

Smart Filtering

Only processes OSC addresses starting with /ma2 to prevent accidental triggers.

Live Monitor UI

Terminal panel displays all OSC and Telnet messages in real time.

Dark/Light Theme

One-click toggle between dark and light modes for any environment.

3. Install and Launch

3.1 Pre-launch Notes

  • Ensure grandMA2 Telnet Server is enabled.
  • Verify MA2 login credentials (default: administrator / admin).
  • Allow program execution if antivirus prompts appear.
  • Ensure OSC sender target IP and Port match this tool's settings.

4.1 Message Prefix Meanings

Message prefixes in the terminal panel indicate their source:

  • <-- [收到 OSC] : Message received from OSC sender
  • --> [發送到 MA2] : Telnet command forwarded to grandMA2
  • [MA2] : MA2 connection status messages
  • [OSC] : OSC server status messages
  • [系統] : Internal system messages

5. Quick Start

5.1 Basic Connection Setup

  1. Identify your grandMA2 host IP address (e.g., 192.168.1.100).
  2. Enable Telnet Server on grandMA2 (default Port 30000).
  3. Launch this tool with default parameters, or specify via command-line.
  4. Check the terminal panel for [MA2] 成功連接到 MA2 Telnet to confirm connection.

5.2 Test Sending OSC Commands

  1. Use an OSC sending tool (TouchOSC, OSCculator, or custom app).
  2. Send OSC message to address /ma2 with parameter as full MA2 command (e.g., Go Executor 1.1).
  3. Or send to address /ma2/Go Executor 1.1.
  4. Verify the terminal panel shows both receive and forward messages.

6. OSC Message Format

6.1 Supported OSC Formats

This tool only processes OSC addresses starting with /ma2. All other messages are filtered out.

Format OSC Address OSC Arguments Result
Format A (Recommended) /ma2 Full command string (e.g., Go Executor 1.1) Go Executor 1.1
Format B /ma2/Go Executor 1.1 Optional extra arguments Go Executor 1.1 [extras]

6.2 Example: Trigger Executor

# Format A: address is /ma2, first argument is the command OSC Address: /ma2 OSC Args: "Go Executor 1.1" → Forwarded to MA2: Go Executor 1.1 # Format B: command in address path OSC Address: /ma2/Go Executor 1.1 OSC Args: (none) → Forwarded to MA2: Go Executor 1.1 # Format B + extra arguments OSC Address: /ma2/SetChannel OSC Args: 1, 255 → Forwarded to MA2: SetChannel 1 255

6.3 Safety Filter

  • All OSC messages not starting with /ma2 are automatically ignored.
  • Terminal shows: [系統] 收到非 MA2 指令，已略過不轉發。
  • This prevents accidental MA2 triggers from other OSC signals.

7. FAQ

Q1: Terminal shows "Connection to MA2 failed"

  • Verify the grandMA2 host IP address is correct.
  • Ensure grandMA2 Telnet Server is enabled.
  • Check that Port 30000 is not blocked by firewall.
  • Try pinging from MA2 to confirm network connectivity.

Q2: OSC received but MA2 not responding

  • Confirm OSC address starts with /ma2.
  • Check MA2 Telnet login status in terminal output.
  • Verify the MA2 command format is correct.
  • Test the command manually on grandMA2 local console.

Q3: OSC sender cannot connect to this tool

  • Use the local LAN IP (not 127.0.0.1) as the OSC target.
  • Ensure OSC port matches this tool's setting (default 8000).
  • Check firewall allows inbound UDP on the specified port.

Q4: No messages appear in terminal panel

  • Confirm the OSC sender is actually transmitting.
  • Verify the OSC address format is correct (must start with /ma2).
  • Try sending test messages with an OSC debugging tool.
